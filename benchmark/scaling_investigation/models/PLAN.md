# Exploratory finite-fit investigation

Declared before calculating the new fits. This is numerical reanalysis of the
completed current-complexity campaign, not a new benchmark or a replacement for
its Google Benchmark result. Every native row, repetition, graph, sampling label,
clock and size is retained. No size is removed as an outlier.

1. Independently parse all 24 native CSVs and Google JSONs, verify archived hashes,
   schedule, integer clocks, exact certificates and graph/twin identities. Rebuild
   3,168 two-call means, all six original through-origin models and Google choices.
2. Fit duration-space least squares on full11 and upper6 for N, NlogN, affine N,
   affine NlogN, and continuous affine hinges at n=16,384, 65,536 and 262,144.
   These three fixed hinges are descriptive size-regime alternatives, not measured
   cache capacities. Report all coefficients, residuals, negative predictions and
   unidentified fits. Negative intercepts are not positive fixed overhead.
3. Evaluate the same fixed models on blocked, future-size holdouts: first five
   sizes predict the next two; first seven predict the next two; first eight
   predict the last three; first nine predict the last two. No test observations
   choose a hinge. Rank-deficient training designs remain unavailable, not repaired
   by choosing an observed breakpoint. Overlapping test blocks are not independent.
4. Sensitivity analysis: refit N/NlogN with pointwise relative-error least squares,
   explicitly distinct from Google's duration-space objective. Report both duration
   normalized RMS and pointwise relative RMS, keeping the same observations.
5. Reconstruct log-log slopes on every trailing window of 4..11 sizes, adjacent
   per-size median slopes, all residuals, and N/NlogN feature similarity. Calculate
   how much the largest sizes contribute to each through-origin design's leverage.
6. Only join clock and logical-work evidence on exact family/n/m/graph/sampler/input
   fingerprint identities. If no archived counters match, make no empirical
   per-operation-cost claim and recommend a matching untimed capture separately.

Library CPU chooses Google's model; manual time uses that same model. Native
CPU/steady and library CPU/manual measure different intervals. Repetitions are not
independent graph samples; retained Boruvka ignores the sampler label. Graph seed
and ascending/descending size order are confounded. No asymptotic theorem, causal
cache attribution, confidence interval or predicted crossover follows from these
exploratory fits. Raw and derived CSVs plus source/input hashes accompany outputs.
