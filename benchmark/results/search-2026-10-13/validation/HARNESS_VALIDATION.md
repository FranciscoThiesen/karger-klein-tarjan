# Five-algorithm harness validation

The final [build/CLI record](final_validation.json) validates the integrated lifted, continuation and crossover dispatch. Both `make mst-search` and `make mst-search-large-stack` compiled successfully with the existing native Make flags and production objects. Nineteen invalid CLI cases were rejected before fixture generation; `--help` passed. No measured solver call was executed by these checks.

The separate large-stack executable has a 536,870,912-byte Mach-O `LC_MAIN` stack. Its `__TEXT,__text` bytes match the default-stack executable exactly: SHA-256 `caf5f0c2e803b765f3f36bd2c40e128ade584db7af7177ec41c5803680b10f07`. This comparison covers executable instructions, not every data section or build provenance. The record also contains full binary hashes and the harness, fixture-header and Makefile hashes. [validate_build.py](validate_build.py) reproduces the CLI and Mach-O checks using the original local paths.

The supplemental [untimed smoke source](untimed_smoke.cpp), [result](untimed_smoke.json) and [stderr log](untimed_smoke.log) cover all 13 pre-existing continuation/crossover families at 128 vertices and two graph seeds: 26 independent certificates, 182 solver checks and 78 malformed-result rejections. The test calls the harness helpers and five solvers directly; it never calls `measure` or `run`. It was compiled before the lifted factory hook, so it is supplemental evidence rather than a final integrated-harness timing test. [initial_validation.json](initial_validation.json) records that earlier harness build's 16 CLI checks and default/large-stack code identity. The final lifted-family correctness gate is documented separately in [SEARCH_FIXTURES_TEST.md](SEARCH_FIXTURES_TEST.md).

The smoke compilation used `/usr/bin/clang++`, `-isysroot $(xcrun --show-sdk-path)`, `-std=c++17 -O3 -Wall -Wextra -march=native -I.`, the temporary smoke source, and the existing `.build` objects for Boruvka, Kruskal, Prim, LCA, union-find, graph utilities, verifier and KKT. Its source retains the original absolute include path. The source review also checked that the compactor repeats the previous harness's production contraction/output operations, tuple-to-`problem` conversion and temporary destruction stay inside the KKT/compactor timer, and result validation, returned-result destruction and row flushing stay outside it.

[harness_validation_archive.json](harness_validation_archive.json) records hashes of the exact copied artifacts. At archival time, the final harness/header and both binary hashes still matched. The root had subsequently added the separate `search_work` Make target; removing that new block reproduces the recorded Makefile hash exactly, and that build-time recipe is retained as [Makefile.at_harness_validation](Makefile.at_harness_validation). The native harness recipes did not change. These are build, correctness and structural checks; none is performance evidence.
